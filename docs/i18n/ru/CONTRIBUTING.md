Спасибо, что заглянули. Это небольшой проект одного автора, поэтому тяжёлого процесса тут
нет — но несколько заметок сделают всё глаже.

## Настройка окружения

```bash
git clone <repo-url> kronos-synapse-dialogue
cd kronos-synapse-dialogue
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Это даёт команду `kronos_synapse` плюс `pytest` и `mypy`. Есть `Makefile` с ярлыками
(`make dev`, `make test`, `make typecheck`), если вам так удобнее.

## Перед открытием PR

- Запустите тесты: `pytest` (или `make test`). Они быстрые и только для CPU.
- Запустите проверку типов: `mypy .`. Кодовая база полностью типизирована; пожалуйста,
  сохраняйте это.
- Держите стиль согласованным с тем, что уже есть: отступ в 4 пробела, аннотации типов у
  публичных функций, короткие комментарии только там, где *почему* неочевидно. Не
  добавляйте docstring, которые просто повторяют сигнатуру.
- Если вы затрагиваете модель или логику упаковки, добавьте или обновите тест в `tests/`.

## Что приветствуется

- Исправления ошибок и более понятные сообщения об ошибках.
- Работа над производительностью на пути обучения на CPU.
- Небольшие, чётко очерченные возможности (новый сэмплер, новый источник корпуса и т. д.).
  Заготовка `DialogueDatasetSource` в `data/sources.py` — очевидная точка расширения.

Для чего-то крупного сначала откройте issue, чтобы обсудить подход, прежде чем тратить на
это время.

## Сообщения коммитов

Короткая строка темы в повелительном наклонении («Add nucleus sampling clamp», а не
«Added...»), с телом, если изменению нужен контекст. По возможности — одно логическое
изменение на коммит.
