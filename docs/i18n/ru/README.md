Языковая модель в стиле GPT только с декодером (~15,3 млн параметров), написанная с нуля на
чистых примитивах `torch.nn` и полностью обученная на CPU. В комплекте — BPE-токенизатор,
конвейер обучения на основе memmap и потоковый чат в CLI, построенный вокруг генератора с
KV-кэшем. Весь стек — модель, данные, обучение, инференс — реализован вручную, без каркаса
`transformers` или `nanoGPT`.

> **Что это (и чем не является).** Эта модель делает **продолжение текста**, а не
> следование инструкциям. Она обучена на художественной прозе (Project Gutenberg), а не на
> размеченных диалоговых парах. Вы вводите текст — она его продолжает. Это не
> ассистент-ролевик. См. [Парадигма чата и ограничения](#парадигма-чата-и-ограничения).

## Быстрый старт

Если вы просто хотите увидеть, как это работает, вот весь цикл от начала до конца:

```bash
# 1. установка
pip install -e ".[dev]"

# 2. положите несколько книг .txt в data/raw/gutenberg/, затем:
kronos_synapse tokenize --corpus-dir data/raw/gutenberg

# 3. обучение (Ctrl+C безопасен; позже можно продолжить с чекпоинта)
kronos_synapse train

# 4. поговорить с ней
kronos_synapse chat checkpoints/best.pt
```

Есть также `Makefile`, если вам удобнее `make tokenize`, `make train`, `make chat`.
Всё работает на CPU — без GPU, без облачного аккаунта, без API-ключей.

## Ключевые особенности

- **Трансформер, собранный вручную.** `CausalSelfAttention`, `MLP`, `TransformerBlock` и
  `MiniGPT` построены напрямую на `nn.Linear`, `nn.LayerNorm`, `nn.Embedding` и
  `nn.Dropout`. Внимание идёт через `F.scaled_dot_product_attention`, который выбирает на
  CPU оптимизированное слитое (fused) ядро.
- **CPU в первую очередь.** Всё работает без CUDA. Цикл обучения балансирует за счёт
  накопления градиента, autocast в `bfloat16`, настраиваемого числа потоков и
  необязательного отката на `torch.compile`.
- **Генерация с KV-кэшем.** Инференс делает один проход предзаполнения (prefill) по
  промпту, а затем декодирует по одному токену против кэшированных ключей/значений — в этом
  и разница между пригодным и непригодным чатом на CPU ноутбука.
- **Управляемый сэмплер.** Температура, top-k, top-p (nucleus) и штраф за повторы —
  все доступны как флаги CLI.
- **Типизированная конфигурация.** Три конфигурации `pydantic-settings` (`ModelConfig`,
  `TrainConfig`, `DataConfig`) заменяют «магические» словари проверенными неизменяемыми
  настройками.

## Архитектура

Стандартный pre-LN GPT-декодер. В таблице ниже — `ModelConfig` по умолчанию.

| Компонент | Значение | Примечания |
|---|---|---|
| `vocab_size` | 12 000 | BPE, обучен с нуля |
| `d_model` | 384 | ширина эмбеддинга / скрытого слоя |
| `n_layers` | 6 | блоки трансформера |
| `n_heads` | 6 | размерность головы = 64 |
| `d_ff` | 1 536 | 4× `d_model`, MLP с GELU |
| `context_length` | 256 | обучаемые абсолютные позиционные эмбеддинги |
| `dropout` | 0.1 | эмбеддинги, выход внимания, выход MLP |
| `lm_head` | связан с `tok_emb` | экономит ~4,6 млн параметров |
| Ядро внимания | `F.scaled_dot_product_attention` | слитое, каузальное при обучении |
| Инициализация весов | схема GPT-2 | `N(0, 0.02)`, остаточные проекции масштабируются на `1/√(2·n_layers)` |

**Бюджет параметров (~15,3 млн):**

| Компонент | Параметры |
|---|---|
| Эмбеддинг токенов (связан с `lm_head`) | 4 608 000 |
| Позиционный эмбеддинг | 98 304 |
| 6 × блок трансформера (attn + MLP + 2× LayerNorm) | 10 626 048 |
| Финальный LayerNorm | 768 |
| **Итого** | **≈ 15 333 120** |

Это число выводится в начале каждого запуска обучения, чтобы вы могли убедиться, что оно в
пределах ±5 % от целевого.

## Требования

- **Python** 3.12 или новее
- **PyTorch** 2.3+ (сборка для CPU; autocast в `bfloat16` эмулируется на Alder Lake, но
  всё равно экономит пропускную способность памяти — есть откат на fp32)
- **Оборудование**: современный многоядерный CPU. Целевая машина при разработке — Intel
  i7-1225U (2P+8E, AVX2, без AVX-512). GPU не требуется.

## Конфигурация

Все настройки находятся в [`config.py`](../../../config.py) в виде неизменяемых моделей
`pydantic-settings`. Редактируйте там значения по умолчанию, чтобы перенастроить модель или
график обучения.

### `ModelConfig`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `vocab_size` | `12_000` | размер словаря BPE |
| `d_model` | `384` | ширина скрытого слоя |
| `n_layers` | `6` | блоки трансформера |
| `n_heads` | `6` | головы внимания |
| `d_ff` | `1536` | внутренняя ширина MLP |
| `context_length` | `256` | максимальная длина последовательности |
| `dropout` | `0.1` | вероятность dropout |

### `TrainConfig`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `num_threads` | `8` | `torch.set_num_threads` |
| `batch_size` | `16` | размер микробатча |
| `grad_accum_steps` | `8` | эффективный батч = `16 × 8 = 128` |
| `max_iters` | `50_000` | шаги оптимизатора |
| `lr` | `3e-4` | пиковая скорость обучения |
| `lr_min` | `1e-5` | нижняя граница косинуса |
| `warmup_iters` | `200` | шаги линейного прогрева |

| `max_grad_norm` | `1.0` | обрезка градиента |
| `use_bf16` | `True` | autocast в `bfloat16` на CPU |
| `compile_model` | `False` | необязательный `torch.compile` с откатом на fp32 |
| `checkpoint_every` | `1_000` | частота чекпоинтов + оценки на валидации |
| `checkpoint_dir` | `checkpoints/` | каталог вывода |

| Параметр | По умолчанию | Описание |
|---|---|---|

| `tokenizer_dir` | `data/processed/tokenizer/` | вывод `tokenizer.json` |

| `val_fraction` | `0.10` | отложенные книги (не виданные при обучении) |

## Подготовка данных

1. Положите файлы `.txt` из Project Gutenberg в `data/raw/gutenberg/`. (Романы XIX — начала
   XX века — Остин, Диккенс, Твен и т. д. — подходят хорошо: много прямой речи и коротких
   реплик.)
2. Обучите токенизатор и упакуйте корпус в отображаемые в память бинарные разбиения:

```bash
kronos_synapse tokenize --corpus-dir data/raw/gutenberg
```

Это создаёт три артефакта в `data/processed/`:

- `tokenizer/tokenizer.json` — BPE-токенизатор
- `train.bin` — обучающие токены как memmap `uint16`
- `val.bin` — валидационные токены (целые книги отложены, поэтому нет утечки окон)

Очистка корпуса происходит автоматически: удаляется шаблонный текст верхнего/нижнего
колонтитула Project Gutenberg, текст нормализуется по Unicode-NFKC, а последовательности
пробелов сворачиваются. Задайте `min_quote_line_ratio` больше 0, чтобы оставить только
документы, насыщенные диалогом в кавычках.

Специальные токены фиксированы: `<pad>=0`, `<unk>=1`, `<bos>=2`, `<eos>=3`. Ролевые токены
(`<user>`/`<bot>`) не добавляются — см. примечание о
[парадигме чата](#парадигма-чата-и-ограничения).

## Обучение

```bash
kronos_synapse train
```

Цикл выводит при старте число параметров, а затем работает с индикатором прогресса Rich.
Каждые `checkpoint_every` шагов он:

- оценивает потерю на валидации,
- добавляет `{step, train_loss, val_loss}` в `logs/train.jsonl`,
- пишет `checkpoints/step_<n>.pt`,
- обновляет `checkpoints/best.pt`, если потеря на валидации улучшилась.

**Продолжить** с любого чекпоинта (состояние оптимизатора и планировщика восстанавливается):

```bash
kronos_synapse train --resume checkpoints/best.pt
```

## Оценка

Оцените чекпоинт на отложенных валидационных книгах:

```bash
kronos_synapse eval checkpoints/best.pt --split val
```

Сообщает перекрёстную энтропию и перплексию (`2^loss`) по разбиению.

## Чат и инференс

```bash
kronos_synapse chat checkpoints/best.pt --temperature 0.8 --top-p 0.9
```

Генерация выводится в терминал потоком, по токену. Первый вызов предзаполняет промпт и
строит KV-кэш; каждый следующий токен декодируется против этого кэша, поэтому длинные
разговоры остаются отзывчивыми.

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--temperature` | `0.8` | заостряет (`<1`) или сглаживает (`>1`) распределение |
| `--top-k` | `50` | оставляет только `k` самых вероятных токенов (`0` отключает) |
| `--top-p` | `0.9` | сэмплирование nucleus (`1.0` отключает) |
| `--repetition-penalty` | `1.1` | понижает вес уже сгенерированных токенов |
| `--max-new-tokens` | `128` | лимит генерации за один ход |

Буфер разговора хранит растущую историю в виде обычного текста и, когда приближается к
`context_length`, обрезает с начала по ближайшей границе предложения (никогда не посреди
слова), сохраняя ведущий `<bos>`. Это скользящее окно *и есть* кратковременная память —
модель читает весь буфер на каждом ходу.

## Парадигма чата и ограничения

Проект намеренно ограничен по охвату и честен в том, что модель на 15 млн параметров может
выучить из непрерывной прозы:

- **Она продолжает текст, а не следует инструкциям.** В обучающих данных нет реплик
  `<user>`/`<bot>`, поэтому у модели нет сигнала для явной смены реплик. То, что вы
  вводите, воспринимается как начало отрывка; модель пишет то, что идёт дальше.
- **Связность локальна.** Ожидайте ~5–6 предложений последовательного стиля и отслеживания
  сущностей в пределах окна контекста. Связность на большом расстоянии не гарантируется.
- **Она только на английском** и с литературным оттенком, потому что корпус — англоязычная
  художественная литература.

Разумная проверка того, что окно контекста действительно используется: упомяните имя
персонажа в начале буфера и убедитесь, что модель всё ещё ссылается на него через 4–6
предложений. Заготовка `DialogueDatasetSource` оставлена в `data/sources.py` как точка
расширения на случай, если позже вы дообучите модель на размеченном диалоге.

## Тестирование

```bash
pytest
```

Юнит-тесты покрывают части, которые с наибольшей вероятностью ломаются незаметно:

- `tests/test_model_shapes.py` — формы тензоров на прямом проходе, число параметров
- `tests/test_attention.py` — формы выхода внимания и поведение KV-кэша
- `tests/test_causal_mask.py` — нет утечки к будущим позициям
- `tests/test_packing.py` — логика разбиения по книгам и бинарной упаковки
- `tests/test_conversation_buffer.py` — обрезка по границам предложений сохраняет `<bos>`

Тесты используют крошечную одноразовую конфигурацию и небольшой токенизатор, обучаемый на
лету, поэтому весь набор завершается за несколько секунд и не требует скачанных данных.

см. в [CONTRIBUTING.md](CONTRIBUTING.md).

## Заметки о производительности

На CPU разработки (i7-1225U) при обучении ожидайте примерно **400–800 токенов/с**, что
соответствует примерно **7–14 часам на эпоху** на корпусе ~20 млн токенов. Пропускная
способность масштабируется с `num_threads`, `use_bf16` и `batch_size × grad_accum_steps`;
подстройте их под свои ядра и память. Генерация с KV-кэшем ощутимо быстрее базового
варианта без кэша на том же CPU — этот разрыв и есть причина, по которой кэширование здесь
обязательно.

## Планы

Примерный порядок, не обещания:

- **Позиционное кодирование RoPE** взамен обучаемых абсолютных позиций, чтобы модель могла
  экстраполировать за пределы `context_length`.
- **Необязательное дообучение на инструкциях** поверх базовой модели, с подключением
  заготовки `DialogueDatasetSource` и настоящих ролевых токенов `<user>`/`<bot>`.
- **Более длинный контекст** (512+), как только позволит пропускная способность обучения.
- **Команда CLI `sample`** для однократного продолжения без интерактивного цикла.
- **Вытеснение KV-кэша**, чтобы сессии чата могли работать бесконечно, а не обрезать текст.

## Частые вопросы

**Почему только CPU?** Потому что смысл был в том, чтобы посмотреть, как далеко зайдёт
написанная с нуля модель на ноутбуке без GPU. Всё настроено вокруг этого ограничения.

**Почему бы просто не использовать `transformers`?** Собрать все части вручную — это и есть
всё упражнение. Вы видите в точности, что делают внимание, KV-кэш и цикл обучения.

**Она отвечает бессмыслицей / повторяется.** Небольшие модели, обученные на ограниченных
данных, так и делают. Дайте ей больше корпуса и больше шагов, понизьте `--temperature` и
немного повысьте `--repetition-penalty`. Также помните, что она *продолжает* текст — она не
отвечает на вопросы (см. [Парадигма чата и ограничения](#парадигма-чата-и-ограничения)).

**Можно ли использовать свой текст вместо Gutenberg?** Да. Подойдёт любой обычный файл
`.txt`; специфичный для Gutenberg шаг — это лишь удаление верхнего/нижнего колонтитула,
которое на другом тексте ничего не делает. Для другого формата добавьте подкласс
`TextCorpusSource` в `data/sources.py`.

**Как сделать её больше/меньше?** Отредактируйте значения по умолчанию в `config.py`
(`d_model`, `n_layers`, `n_heads`, `context_length`). Число параметров выводится в начале
обучения, так что вы сможете проверить, где оказались.
